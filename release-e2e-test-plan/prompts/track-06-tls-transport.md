# Track 06 — TLS & transport security

**You are** a transport-security tester. You care about what travels in cleartext,
whether TLS can be enforced, whether the auto-generated certificate is sane, and
whether a client can be tricked or downgraded.

**Read first:** `ENVIRONMENT-SETUP.md` (§2 TLS, §6 C8) and `REPORT-TEMPLATE.md`.
**Write** to `reports/track-06-tls-transport.md`.

## SUT
`documentdb-local:pg17-0.116.0`. TLS modes come from `TLS_MODE` / gateway config:
`allowTLS` (default), `requireTLS`, `disabled`. With no mounted cert the gateway
**auto-generates a self-signed cert** (`PemAutoGenerated`).

## What to test (checklist)

1. **Default `allowTLS`.** Confirm the gateway accepts **both** a TLS client and a
   **plaintext** client on the same port. Demonstrate a successful **non-TLS**
   connect (e.g. `mongosh --tls=false` / a driver with `tls=false`) authenticating
   and querying. Document that credentials + data then travel in cleartext — over
   `allowTLS` this is possible, and it's the default. Assess the risk and whether
   the default should be `requireTLS` (finding for the release owner).
2. **`requireTLS`.** Start with `TLS_MODE=requireTLS`. Confirm a plaintext client
   is **rejected** and only TLS succeeds. A plaintext client that still gets
   through under `requireTLS` is **S1**.
3. **`disabled` is not "off" (finding-seed C8).** Start with `TLS_MODE=disabled`.
   Confirm the documented surprising behavior: the gateway has no plain-only mode,
   so it **still accepts TLS** (and plain) and prints a warning that `disabled`
   does not turn TLS off. Confirm the warning is actually emitted. A user relying
   on `disabled` to force plaintext-only will not get it — weigh the UX/security
   impact (S3/S4 + doc).
4. **Auto-generated certificate quality.** Capture the server cert
   (`openssl s_client -connect localhost:10260 -starttls`? — MongoDB wire is not
   STARTTLS; use `openssl s_client -connect localhost:10260` against a TLS-required
   instance, or extract via a driver). Inspect: key type/size (RSA≥2048 or ECDSA),
   signature algorithm (no SHA-1/MD5), validity window (not absurdly long/expired),
   SAN present, self-signed as expected. A weak key or SHA-1 signature is S3.
5. **Mounted custom cert.** Generate a cert+key, mount them, start with
   `--cert-path`/`--key-file`. Confirm the gateway serves **your** cert (matching
   fingerprint) and that a client validating against your CA connects **without**
   `--tlsAllowInvalidCertificates`. Confirm the "both or neither" rule: supplying
   only `--cert-path` (no key) must fail fast with a clear error.
6. **Downgrade / protocol floor.** Probe supported TLS versions and ciphers
   (`nmap --script ssl-enum-ciphers -p 10260`, or `testssl.sh`). Confirm TLS 1.0/1.1
   and export/NULL/anonymous ciphers are **not** offered; TLS 1.2+ only. Offering
   TLS 1.0/1.1 or weak ciphers is S2/S3.
7. **Cert validation by the client.** Confirm that with the default self-signed
   cert, a **strict** client (no allow-invalid) correctly **refuses** to connect
   (proving the client-side validation path works), and that
   `--tlsAllowInvalidCertificates` is genuinely required. A strict client that
   connects anyway means validation is broken (S2).
8. **Backend PG transport.** If `--allow-external-connections true`, check whether
   the exposed internal PG port offers TLS or is cleartext, and what that implies.
   Hand exposure specifics to Track 07.
9. **Certificate persistence.** Restart the container/gateway; confirm the
   auto-generated cert is either stably reused or regenerated — and that clients
   pinning the previous cert are handled predictably (document which).

## Expected results
`requireTLS` truly enforces; `disabled` warns and still allows TLS (C8); auto-cert
is modern (≥2048-bit/ECDSA, SHA-256+, has SAN); custom cert served correctly;
no TLS 1.0/1.1 or weak ciphers; strict client rejects self-signed as it should.

## Report
`REPORT-TEMPLATE.md`. Drive the C8 verdict. Attach `nmap`/`testssl` output and the
captured server cert under `reports/artifacts/track-06-*`. Any plaintext-under-
requireTLS or broken client validation is S1/S2 at the top.
